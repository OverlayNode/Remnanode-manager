# Remnawave Node Manager

Interactive bootstrap and management script for a Remnawave Node.

The manager is designed for a separate Node VPS running Ubuntu/Debian and supports a plain RemnaNode installation or a self-contained node with local TLS, Nginx Selfsteal and generated Xray profiles.

## Features

- Install Docker Engine + Docker Compose
- Install and configure UFW
- Keep OpenSSH (`22/tcp`) reachable
- Restrict Remnawave Node API (`2222/tcp`) to the Panel IP/CIDR when supplied
- Install/update `remnawave/node:latest`
- Local Let's Encrypt certificates through `acme.sh`
- Automatic certificate renewal and `nginx-selfsteal` restart
- Nginx Selfsteal over `/dev/shm/nginx.sock`
- Generic cloud landing page generated from your domain/service name
- The landing page **does not submit or store login/password fields**
- Generate Remnawave Xray profiles for:
  - VLESS RAW + REALITY
  - VLESS XHTTP + REALITY
  - Hysteria2 (UDP/TLS)
- Update containers
- SSL management
- Diagnostics
- Domain/site-name changes
- Reality key rotation
- Inbound reconfiguration/profile regeneration
- Removal of the node stack

## Quick start

Download and run as root:

```bash
curl -fsSL https://raw.githubusercontent.com/YOUR_USER/YOUR_REPO/main/remnanode-manager.sh \
  -o /root/remnanode-manager.sh

chmod +x /root/remnanode-manager.sh
/root/remnanode-manager.sh
```

Or:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/YOUR_USER/YOUR_REPO/main/remnanode-manager.sh)
```

Replace `YOUR_USER/YOUR_REPO` after publishing the repository.

## Selfsteal installation

The installer asks for:

- `SECRET_KEY` generated by Remnawave Panel when the Node is created
- Panel IP/CIDR for access to TCP `2222`
- Node domain, for example `de01.example.com`
- Service name shown on the cloud landing page
  - leave empty to display the domain itself
- Email used by Let's Encrypt/acme.sh
- Inbounds to generate

### Inbound selection

You can select one or more:

```text
1. VLESS RAW + REALITY + Selfsteal
2. VLESS XHTTP + REALITY + Selfsteal
3. Hysteria2 (UDP + TLS)
4. All
```

When RAW and XHTTP are both enabled, the manager uses different TCP ports because they are separate Xray inbounds.

Default layout:

| Component | Default |
|---|---:|
| SSH | TCP 22 |
| RemnaNode API | TCP 2222 |
| ACME HTTP-01 | TCP 80 |
| VLESS RAW / REALITY | TCP 443 |
| VLESS XHTTP / REALITY when RAW is also enabled | TCP 8443 |
| Hysteria2 | UDP 443 |

TCP `443` and UDP `443` do not conflict, so VLESS/REALITY and Hysteria2 can both use port 443.

## XHTTP

The manager generates a random XHTTP path and lets you choose:

- `stream-one` (default)
- `stream-up`
- `packet-up`
- `auto`

The generated XHTTP inbound does not use `xtls-rprx-vision`. Client settings must match the generated path, mode, SNI, Reality public key and Short ID.

## Hysteria2

The generated inbound uses the Xray Hysteria protocol with:

```json
"protocol": "hysteria",
"version": 2,
"network": "hysteria",
"security": "tls"
```

The Node-local certificate is mounted into the RemnaNode container:

```text
/opt/remnanode/ssl/fullchain.pem
/opt/remnanode/ssl/privkey.pem
```

Hysteria2 uses UDP, so remember that upstream provider/security-group firewalls must allow the selected UDP port in addition to UFW.

## SSL

Certificates are issued on the Node itself:

```bash
~/.acme.sh/acme.sh --issue \
  --standalone \
  -d node.example.com \
  --server letsencrypt
```

Production copies are installed to:

```text
/opt/remnanode/ssl/fullchain.pem
/opt/remnanode/ssl/privkey.pem
```

The manager registers a deploy hook that restarts `nginx-selfsteal` after a successful certificate update.

Port `80/tcp` must be reachable for standalone HTTP-01 renewals.

## Landing page

The landing page is deliberately generic.

For example, with:

```text
Domain: de01.example.com
Service name: Example
```

the page displays:

```text
Example Cloud
Gateway: de01.example.com
```

If the service name is left empty, the domain itself is used.

The login form is visual only. JavaScript prevents submission and does not read, transmit or persist credentials.

## Remnawave Panel

After installation, copy the generated profile:

```bash
cat /opt/remnanode/profiles/xray-profile.json
```

into a Remnawave Config Profile and assign it to the intended Node.

Connection details are written to:

```bash
cat /opt/remnanode/profiles/profile-info.txt
```

Be careful not to assign unrelated profiles/inbounds that bind the same TCP/UDP port on the same Node.

## Firewall

The manager uses UFW. It can reset existing UFW rules during install if you approve.

If you use a cloud-provider firewall/security group, you must also allow the same ports there.

For better security, provide the Panel IP/CIDR so TCP `2222` is not exposed globally.

## Security notes

- Do not publish `.env`, `reality.env`, `/opt/remnanode/ssl/` or generated private-key-containing profile files.
- Rotate a Reality key if it is accidentally disclosed.
- The script leaves Docker installed when removing a node.
- Removing the node stack does not automatically remove SSH access.
- The cloud page is not intended to imitate a third-party brand or collect user credentials.
